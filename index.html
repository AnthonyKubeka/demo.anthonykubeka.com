Every deploy starts with a commit

The whole server rebuilds from the repo, so nothing important lives only in my head.

    04

    The crew

    I send a text or a voice note to a Telegram bot. An agent on Normandy does the work in its own workspace. I get back a question with buttons, a verified result, or a line in the evening digest.

    The phone is the control channel

    Every step I take has to work from an iPhone. If a step needs a terminal, I log it as a defect.

    Act, then report

    Agents act without asking, apart from a short ask-first list. Every change lands in a log line and in the digest.

    Every account is crew

    An account is a subscription and its quota, from any vendor. Safety belongs to the task's workspace, so I can move a task from Claude to Codex halfway through.

    How a request moves

      What asks first

      • Deleting data that can't be restored
      • Moving money
      • Messaging people
      • Posting in public
      • Exposing a secret
      • Changing an access path

      A deletion covered by a verified backup snapshot counts as reversible, so it goes ahead. An access-path change runs with an automatic revert timer.

      The score so far

      One dead login failed the same job 3 times in a row. The worker gets its token through a wrapper now.

      Known limit, from my own guide: the ask-first guard reads a request once, at intake. Guards at the tool level are next.

      05

      One instruction file, every agent

      Claude Code and Codex both work on this machine, and they have to follow the same rules. So there's 1 file. Each agent's config path is a symlink to it, and a pre-commit hook fails the commit if a link has turned into a regular file.

      Two copies drift. One inode can't.

      The same goes for rules. A rule that changes behaviour gets updated on every agent surface in the same session. A rule changed in 1 place is a bug.

      Agents also read the web through local tools on this box: a private metasearch instance and a headless browser. I get the source text, and every agent gets the same input.

      06
      
        
      Shared memory
      
      
      
      
      
        
      
          
      The agents share 1 Markdown vault. Raw sources go in and never change. The wiki pages belong to the agents: they write them, index them and log every operation.
      
          
      It's close to Karpathy's LLM-wiki pattern: immutable sources, a wiki the model owns, and a schema file that says how.
      
          
      Background agents never touch the live vault. Each one gets a job copy and an integrator merges it. A conflict becomes a question on my phone.
